# DNS + Web / FTP 통합 서비스 구축

Master DNS에서 등록한 Domain을 실제 Web Server와 FTP Server에 연결하여 DNS 조회부터 Application Service 접속까지 전체 흐름을 검증하였다.

- `www.bangkyu.com` → Apache Web Server
- `ftp.bangkyu.com` → vsftpd FTP Server
- FTP 파일 Upload / Download
- SHA-256을 이용한 파일 무결성 검증

---

## 1. 실습 환경

| 구분 | Hostname | IP | 역할 |
|---|---|---|---|
| Server-A | Server-A | 192.168.111.100 | Master DNS / Web Server |
| Server-B | Server-B | 192.168.111.200 | FTP Server |
| Client | Client-L | 192.168.111.150 | DNS / Web / FTP Client |

Domain 구성:

```text
www.bangkyu.com
→ 192.168.111.100

ftp.bangkyu.com
→ 192.168.111.200
```

전체 구조:

```text
                    Master DNS
                  192.168.111.100
                         |
              +----------+----------+
              |                     |
      www.bangkyu.com        ftp.bangkyu.com
              |                     |
      192.168.111.100        192.168.111.200
              |                     |
         Apache HTTP              vsftpd
          TCP 80                 TCP 21
              |                     |
              +----------+----------+
                         |
                      Client-L
                   192.168.111.150
```

# Server-A DNS Resolver 문제 해결

## 8. Domain을 이용한 Web 접속 실패

다음 명령으로 Domain 접속을 시도하였다.

```bash
curl http://www.bangkyu.com
```

오류:

```text
curl: (6) Could not resolve host: www.bangkyu.com
```

Apache 자체는 정상 동작하지만 Server-A에서 Domain Name을 IP 주소로 변환하지 못하였다.

---

## 9. Server-A DNS 설정 확인

```bash
cat /etc/resolv.conf
```

확인 결과:

```text
# Generated by NetworkManager
nameserver 192.168.111.2
```

NetworkManager 확인:

```bash
nmcli device show ens160 | grep -E 'GENERAL.CONNECTION|IP4.DNS'
```

```text
GENERAL.CONNECTION:                     ens160
IP4.DNS[1]:                             192.168.111.2
```

Server-A 자신이 구축한 DNS Server `192.168.111.100`이 아니라 VMware DNS `192.168.111.2`를 사용하고 있었다.

따라서 내부에서 직접 생성한 `bangkyu.com` Zone을 해석하지 못하였다.

---

## 10. Server-A DNS Server 변경

Server-A가 자기 자신의 DNS Server를 사용하도록 변경하였다.

```bash
nmcli connection modify ens160 ipv4.ignore-auto-dns yes
nmcli connection modify ens160 ipv4.dns "192.168.111.100"

nmcli device reapply ens160
```

DNS 이름 해석 확인:

```bash
getent hosts www.bangkyu.com
getent hosts ftp.bangkyu.com
```

결과:

```text
192.168.111.100 www.bangkyu.com
192.168.111.200 ftp.bangkyu.com
```

# FTP File Transfer

## 20. Client 테스트 파일 생성

Client-L에서:

```bash
cd /tmp

echo "FTP upload test from Client-L" > ftp-test.txt

cat ftp-test.txt
```

결과:

```text
FTP upload test from Client-L
```

---

## 21. FTP Upload 과정에서 발생한 오류

Client-L에서:

```bash
ftp ftp.bangkyu.com
```

접속 후:

```text
ftp> put /tmp/ftp-test.txt
```

실행 결과:

```text
local: /tmp/ftp-test.txt remote: /tmp/ftp-test.txt
227 Entering Passive Mode (192,168,111,200,89,48).
553 Could not create file.
```

FTP Client가 Remote File Name도 `/tmp/ftp-test.txt`로 처리하면서 파일을 생성하지 못하였다.

FTP의 현재 Server Directory는:

```text
/home/guest
```

였다.

Remote File Name을 명확하게 지정하여 `/home/guest`에 파일이 저장되도록 처리하였다.

예:

```text
put /tmp/ftp-test.txt ftp-test.txt
```

---

## 22. Server-B Upload 파일 확인

Server-B:

```bash
ls -l /home/guest
```

실제 결과:

```text
total 4
-rw-r--r--. 1 guest guest 30 Sep 14 12:26 ftp-test.txt
```

파일 내용 확인:

```bash
cat /home/guest/ftp-test.txt
```

결과:

```text
FTP upload test from Client-L
```

Client-L에서 전송한 파일이 Server-B의 `/home/guest`에 정상적으로 저장된 것을 확인하였다.

# 주요 문제 해결

## 30. Domain Web 접속 실패

증상:

```text
curl: (6) Could not resolve host: www.bangkyu.com
```

원인:

```text
Server-A DNS
192.168.111.2

Master DNS
192.168.111.100
```

Server-A가 VMware DNS를 사용하고 있어 내부 `bangkyu.com` Zone을 조회하지 못하였다.

해결:

```bash
nmcli connection modify ens160 ipv4.ignore-auto-dns yes
nmcli connection modify ens160 ipv4.dns "192.168.111.100"
nmcli device reapply ens160
```

확인:

```text
192.168.111.100 www.bangkyu.com
192.168.111.200 ftp.bangkyu.com
```

이후:

```bash
curl http://www.bangkyu.com
```

정상 동작하였다.

---

## 31. FTP Upload 실패

증상:

```text
553 Could not create file.
```

Upload 시:

```text
local: /tmp/ftp-test.txt
remote: /tmp/ftp-test.txt
```

로 처리되었다.

Remote 저장 File Name을 명확하게 지정하여 처리하였다.

```text
put /tmp/ftp-test.txt ftp-test.txt
```

최종적으로 Server-B에서:

```text
/home/guest/ftp-test.txt
```

파일이 생성된 것을 확인하였다.

# 실습 결과

이번 실습을 통해 다음 내용을 확인하였다.

```text
DNS
✓ www.bangkyu.com → 192.168.111.100
✓ ftp.bangkyu.com → 192.168.111.200

Web
✓ Apache 설치 및 실행
✓ TCP 80 Listen 확인
✓ Firewall HTTP 허용
✓ IP 기반 Web 접속
✓ Domain 기반 Web 접속

FTP
✓ vsftpd 설치 및 실행
✓ TCP 21 Listen 확인
✓ Domain 기반 FTP 접속
✓ guest 사용자 로그인
✓ Passive Mode Directory 조회
✓ File Upload
✓ File Download

검증
✓ DNS와 실제 Application Service 연결
✓ SHA-256을 이용한 전송 파일 무결성 확인
```

최종 구조:

```text
                     Client-L
                  192.168.111.150
                         |
                         | DNS Query
                         v
                  192.168.111.100
                    Master DNS
                         |
             +-----------+-----------+
             |                       |
             v                       v
     www.bangkyu.com         ftp.bangkyu.com
     192.168.111.100          192.168.111.200
             |                       |
          TCP 80                   TCP 21
             |                       |
          Apache                   vsftpd
             |                       |
         Web Page              FTP File Transfer
                                     |
                              Upload / Download
                                     |
                              SHA-256 일치
```

Master DNS에서 구성한 DNS Record를 실제 Apache 및 vsftpd Service와 연결하고, Client가 Domain Name을 통해 Server Service에 접근하는 전체 과정을 검증하였다.

또한 FTP를 통한 파일 Upload / Download 후 SHA-256 Hash를 비교하여 전송 전후 파일의 무결성까지 확인하였다.

# Rocky Linux 파일 권한 관리

> Linux 시스템에서 **파일과 디렉터리의 권한(Permission), 소유권(Ownership), 기본 권한(umask), 특수 권한**을 관리하는 방법

---

# 1. 파일 권한 — Permission

Linux는 여러 사용자가 동시에 사용하는 멀티유저 운영체제이다.

여러 사용자가 동일한 파일 시스템을 사용하기 때문에 다른 사용자의 파일을 임의로 읽거나 수정하지 못하도록 권한을 이용하여 접근을 제어한다.

Linux의 파일 권한은 다음 세 가지 사용자 범위로 구분된다.

- **Owner** : 파일 또는 디렉터리의 소유자
- **Group** : 파일 또는 디렉터리의 소유 그룹
- **Other** : 소유자와 소유 그룹에 속하지 않는 사용자

각 사용자 범위에는 `r`, `w`, `x` 권한을 설정할 수 있다.

| 권한 | 숫자 | 의미 |
| --- | ---: | --- |
| `r` | 4 | 읽기(Read) |
| `w` | 2 | 쓰기(Write) |
| `x` | 1 | 실행(Execute) |
| `-` | 0 | 권한 없음 |

---

## 파일과 디렉터리의 권한 의미

같은 `r`, `w`, `x`라도 파일과 디렉터리에서 의미가 다르다.

| 권한 | 파일 | 디렉터리 |
| --- | --- | --- |
| `r` | 파일 내용 읽기 | 디렉터리 내부 목록 확인 |
| `w` | 파일 내용 수정 | 파일 및 디렉터리 생성, 삭제, 이름 변경 |
| `x` | 실행 파일 실행 | 디렉터리 접근 및 이동 |

예시:

```bash
ls -l test.txt
```

```text
-rw-r--r--
```

권한을 나누어 보면 다음과 같다.

```text
-   rw-   r--   r--
│    │     │     │
│    │     │     └─ Other
│    │     └─────── Group
│    └───────────── Owner
└────────────────── 파일 종류
```

파일 종류는 다음과 같이 표시된다.

- `-` : 일반 파일
- `d` : 디렉터리
- `l` : 심볼릭 링크

---

# 2. 권한 변경 — `chmod`

파일 또는 디렉터리의 권한을 변경하는 명령어

### 기본 형식

```bash
chmod [권한] [파일 또는 디렉터리]
```

예시:

```bash
chmod 755 test.sh
```

→ `test.sh`의 권한을 `rwxr-xr-x`로 변경

---

## 숫자를 이용한 권한 변경

권한의 숫자는 `r`, `w`, `x` 값을 더하여 계산한다.

```text
r = 4
w = 2
x = 1
```

예를 들어:

```text
7 = 4 + 2 + 1 = rwx
6 = 4 + 2     = rw-
5 = 4 + 1     = r-x
4 = 4         = r--
```

주요 권한 예시:

| 권한 | 의미 |
| --- | --- |
| `755` | `rwxr-xr-x` |
| `644` | `rw-r--r--` |
| `600` | `rw-------` |
| `640` | `rw-r-----` |

예시:

```bash
chmod 640 test.txt
```

→ Owner는 읽기/쓰기, Group은 읽기, Other는 권한 없음

---

## 기호를 이용한 권한 변경

사용자 범위와 연산자를 이용하여 특정 권한만 추가하거나 제거할 수 있다.

| 기호 | 의미 |
| --- | --- |
| `u` | Owner(User) |
| `g` | Group |
| `o` | Other |
| `a` | All |
| `+` | 권한 추가 |
| `-` | 권한 제거 |
| `=` | 권한 지정 |

예시:

```bash
chmod u+x test.sh
chmod g+w test.txt
chmod o-r test.txt
```

- `u+x` : 소유자에게 실행 권한 추가
- `g+w` : 그룹에 쓰기 권한 추가
- `o-r` : 기타 사용자의 읽기 권한 제거

---

# 3. 소유권 — Ownership

Linux의 파일과 디렉터리는 사용자 소유자와 소유 그룹 정보를 가진다.

- **Owner** : 파일 또는 디렉터리의 소유 사용자
- **Group** : 파일 또는 디렉터리의 소유 그룹

소유권은 `ls -l` 명령어로 확인할 수 있다.

```bash
ls -l test.txt
```

예시:

```text
-rw-r--r--. 1 user1 testgroup 0 test.txt
```

```text
user1      → 소유자
testgroup  → 소유 그룹
```

---

# 4. 소유권 변경 — `chown`

파일 또는 디렉터리의 소유자를 변경하는 명령어

### 기본 형식

```bash
chown [소유자] [파일]
```

예시:

```bash
chown user1 test.txt
```

→ `test.txt`의 소유자를 `user1`으로 변경

소유자와 소유 그룹을 동시에 변경할 수도 있다.

```bash
chown user1:testgroup test.txt
```

→ 소유자 `user1`, 소유 그룹 `testgroup`으로 변경

---

# 5. 소유 그룹 변경 — `chgrp`

파일 또는 디렉터리의 소유 그룹만 변경하는 명령어

### 기본 형식

```bash
chgrp [그룹] [파일]
```

예시:

```bash
chgrp testgroup test.txt
```

→ `test.txt`의 소유 그룹을 `testgroup`으로 변경

---

# 6. 기본 권한 — `umask`

`umask`는 새로 생성되는 파일과 디렉터리의 권한 중 일부를 제한하는 값이다.

일반적으로 새 파일과 디렉터리는 다음 권한을 기준으로 생성된다.

```text
디렉터리 : 777
파일     : 666
```

새 파일은 일반적으로 실행 권한 없이 생성되기 때문에 `666`을 기준으로 한다.

현재 `umask` 값 확인:

```bash
umask
```

예시:

```text
0022
```

`umask 0022` 환경에서는 일반적으로 다음과 같은 권한으로 생성된다.

```text
디렉터리 → 755 (rwxr-xr-x)
파일     → 644 (rw-r--r--)
```

---

## umask 변경

예시:

```bash
umask 0002
```

현재 값 확인:

```bash
umask
```

```text
0002
```

`umask 0002` 환경에서는 일반적으로 다음과 같이 생성된다.

```text
디렉터리 → 775 (rwxrwxr-x)
파일     → 664 (rw-rw-r--)
```

`umask`는 기존 파일의 권한을 변경하는 것이 아니라 새로 생성되는 파일과 디렉터리의 기본 권한에 영향을 준다.

---

# 7. 특수 권한

Linux에는 일반적인 `r`, `w`, `x` 외에 특정 상황에서 사용하는 특수 권한이 있다.

특수 권한은 다음 세 가지가 있다.

| 특수 권한 | 숫자 | 주요 용도 |
| --- | ---: | --- |
| Set-UID | `4xxx` | 실행 시 파일 소유자의 유효 사용자 권한 사용 |
| Set-GID | `2xxx` | 그룹 권한 실행 또는 디렉터리의 그룹 상속 |
| Sticky Bit | `1xxx` | 공유 디렉터리에서 다른 사용자의 파일 삭제 제한 |

---

# 8. Set-UID

Set-UID는 주로 실행 파일에 설정하는 특수 권한이다.

Set-UID가 설정된 프로그램을 실행하면 프로그램이 실행되는 동안 파일 소유자의 유효 사용자 권한(EUID)으로 동작한다.

숫자로 표현할 때 앞자리에 `4`를 사용한다.

```text
일반 권한 : 755
Set-UID   : 4755
```

권한 표시에서는 Owner의 실행 권한 `x` 위치에 `s`가 표시된다.

일반 권한:

```text
-rwxr-xr-x
```

Set-UID 적용:

```text
-rwsr-xr-x
   ↑
   s = Set-UID
```

대표적인 예:

```bash
ls -l /usr/bin/passwd
```

예시:

```text
-rwsr-xr-x. 1 root root ... /usr/bin/passwd
```

일반 사용자는 `/etc/shadow`를 직접 수정할 권한이 없지만 `passwd` 프로그램은 필요한 작업을 수행할 때 파일 소유자인 `root`의 유효 사용자 권한으로 동작할 수 있다.

Set-UID는 일반 사용자에게 `root` 계정 자체를 부여하는 기능이 아니다.

또한 일반 사용자에게 `/etc/shadow`의 쓰기 권한을 직접 부여하는 기능도 아니다.

실행 중인 프로그램의 유효 사용자 권한이 파일 소유자 기준으로 동작하는 기능이다.

---

# 9. Set-GID

Set-GID는 파일 또는 디렉터리에 설정할 수 있는 특수 권한이다.

특히 여러 사용자가 함께 사용하는 공유 디렉터리에서 많이 사용한다.

일반적으로 사용자가 파일을 생성하면 새 파일의 소유 그룹은 파일을 만든 사용자의 기본 그룹으로 설정된다.

예:

```text
user1이 파일 생성
→ 소유자 : user1
→ 소유 그룹 : user1
```

하지만 Set-GID가 설정된 디렉터리 안에서 파일이나 디렉터리를 생성하면 새로 생성된 파일과 디렉터리는 부모 디렉터리의 소유 그룹을 상속한다.

숫자로 표현할 때 앞자리에 `2`를 사용한다.

```text
일반 권한 : 770
Set-GID   : 2770
```

설정 예시:

```bash
chmod 2770 /project
```

권한 표시:

```text
drwxrws---
```

Group의 실행 권한 `x` 위치에 `s`가 표시된다.

예를 들어 `/project`의 소유 그룹이 `teamA`라면:

```text
/project
└─ 소유 그룹 : teamA
```

Set-GID 적용 후:

```text
user1이 파일 생성 → user1:teamA
user2가 파일 생성 → user2:teamA
user3가 파일 생성 → user3:teamA
```

따라서 팀 프로젝트, 공동 작업 폴더, 부서별 공유 디렉터리에서 파일의 소유 그룹을 통일하는 데 사용할 수 있다.

---

# 10. Sticky Bit

Sticky Bit는 여러 사용자가 함께 사용하는 공유 디렉터리에서 다른 사용자의 파일을 임의로 삭제하거나 이름을 변경하는 것을 제한할 때 사용하는 특수 권한이다.

예를 들어 `777` 권한의 공유 디렉터리는 모든 사용자가 쓰기 권한을 가지므로 다른 사용자가 생성한 파일도 삭제할 수 있다.

```bash
chmod 777 /share
```

Sticky Bit를 적용하려면 앞자리에 `1`을 사용한다.

```bash
chmod 1777 /share
```

권한 확인:

```bash
ls -ld /share
```

예시:

```text
drwxrwxrwt
```

Other의 실행 권한 `x` 위치에 `t`가 표시된다.

Sticky Bit가 적용된 디렉터리에서는 일반적으로 다음 사용자가 파일을 삭제하거나 이름을 변경할 수 있다.

- 파일의 소유자
- 디렉터리의 소유자
- `root`

따라서 여러 사용자가 파일을 생성해야 하지만 서로의 파일은 삭제하면 안 되는 공유 디렉터리에 적합하다.

대표적인 예:

```bash
ls -ld /tmp
```

# 11. 파일과 디렉터리 권한의 차이

파일과 디렉터리는 같은 `r`, `w`, `x` 권한을 사용하지만 동작 방식에는 차이가 있다.

### 파일

```text
r → 파일 내용 읽기
w → 파일 내용 수정
x → 파일 실행
```

### 디렉터리

```text
r → 디렉터리 내부 목록 확인
w → 파일 및 디렉터리 생성, 삭제, 이름 변경
x → 디렉터리 접근 및 이동
```

특히 파일의 삭제와 이름 변경은 파일 자체의 `w` 권한보다 부모 디렉터리의 권한이 중요하다.

---

# 12. 권한 관리 주요 명령어

| 명령어 | 기능 | 사용 예시 |
| --- | --- | --- |
| `ls -l` | 파일 권한 및 소유권 확인 | `ls -l test.txt` |
| `ls -ld` | 디렉터리 자체 권한 확인 | `ls -ld testdir` |
| `chmod` | 파일 및 디렉터리 권한 변경 | `chmod 755 test.sh` |
| `chown` | 소유자 또는 소유자/그룹 변경 | `chown user1:testgroup test.txt` |
| `chgrp` | 소유 그룹 변경 | `chgrp testgroup test.txt` |
| `umask` | 새 파일 및 디렉터리의 기본 권한 제한 | `umask 0022` |

---

# 13. 특수 권한 핵심 정리

```text
4xxx = Set-UID
2xxx = Set-GID
1xxx = Sticky Bit
```

예:

```text
4755 → Set-UID + 755
2770 → Set-GID + 770
1777 → Sticky Bit + 777
```

표시 방식:

```text
Set-UID    → Owner의 x 위치에 s
Set-GID    → Group의 x 위치에 s
Sticky Bit → Other의 x 위치에 t
```

---

# 14. 파일 권한 관리 전체 흐름

```text
파일 또는 디렉터리 확인
        ↓
ls -l / ls -ld
        ↓
권한 확인
        ↓
Owner / Group / Other
        ↓
r / w / x 확인
        ↓
필요한 권한으로 변경
        ↓
chmod
        ↓
소유자 또는 소유 그룹 변경
        ↓
chown / chgrp
        ↓
새 파일의 기본 권한 관리
        ↓
umask
        ↓
공유 디렉터리 또는 특수 실행 환경
        ↓
Set-UID / Set-GID / Sticky Bit
```

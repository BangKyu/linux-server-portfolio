# Linux DHCP Server 구성 및 IP 자동 할당 실습

## 실습 개요

Linux 환경에서 DHCP Server를 구성하고 Linux 및 Windows Client에게 IP 주소를 자동으로 할당하는 방법을 실습하였다.

DHCP 동작 과정인 DORA를 서버 로그에서 확인하고 `/var/lib/dhcpd/dhcpd.leases` 파일을 이용하여 실제 IP 임대 정보를 확인하는 방법을 실습하였다.

---

## 실습 과정

### 1. Server-A 네트워크 정보 확인

Server-A의 IP 주소와 네트워크 인터페이스를 확인하였다.

```bash
[root@Server-A ~]# ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128
ens160           UP             192.168.111.100/24 fe80::20c:29ff:fedd:cda/64
```

Routing Table 확인

```bash
[root@Server-A ~]# ip route
default via 192.168.111.2 dev ens160 proto static metric 100
192.168.111.0/24 dev ens160 proto kernel scope link src 192.168.111.100 metric 100
```

DNS 확인

```bash
[root@Server-A ~]# cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 192.168.111.2
```

Server-A가 `192.168.111.100/24`를 사용하고 있으며 Gateway가 `192.168.111.2`인 것을 확인하였다.

---

### 2. VMware DHCP Server 중지

VMware DHCP Server와 Server-A의 DHCP Server가 동시에 동작하지 않도록 VMware의 기본 DHCP 기능을 중지하였다.

VMware Workstation에서 다음 경로로 설정하였다.

```text
Edit
 → Virtual Network Editor
   → Change Settings
     → VMnet8
       → Use local DHCP service to distribute IP address to VMs
         → 체크 해제
```

VMware의 NAT 기능과 Gateway 기능은 그대로 유지하고 DHCP 기능만 중지하였다.

```text
VMnet8 NAT       → 유지
Gateway          → 192.168.111.2
VMware DHCP      → 중지
Server-A DHCP    → 사용
```

### 3. Client-L의 기존 DHCP 주소 제거

VMware DHCP Server를 중지한 후 Client-L의 네트워크 연결을 다시 활성화하였다.

```bash
[guest@Client-L ~]$ sudo nmcli connection down ens160
[guest@Client-L ~]$ sudo nmcli connection up ens160
```

IP 주소 확인

```bash
[guest@Client-L ~]$ ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128
ens160           UP
```

NetworkManager 연결 상태 확인

```bash
[guest@Client-L ~]$ nmcli connection show

ens160  87cd2bd0-c565-32a7-8a18-bb8b9fafc2b8  ethernet  --
```

DHCP Server가 없는 상태에서는 Client-L이 IPv4 주소를 할당받지 못하는 것을 확인하였다.

### 4. DHCP 설정 파일 구성

DHCP Server 설정 파일을 다음과 같이 구성하였다.

```bash
[root@Server-A ~]# vi /etc/dhcp/dhcpd.conf
```

설정 내용

```text
authoritative;
ddns-update-style none;

subnet 192.168.111.0 netmask 255.255.255.0 {
    option routers 192.168.111.2;
    option domain-name-servers 168.126.63.1, 8.8.8.8;
    option subnet-mask 255.255.255.0;
    option broadcast-address 192.168.111.255;

    range 192.168.111.150 192.168.111.180;

    default-lease-time 86400;
    max-lease-time 864000;
}
```

설정한 주요 DHCP 정보는 다음과 같다.

```text
Network          : 192.168.111.0/24
Gateway          : 192.168.111.2
Broadcast        : 192.168.111.255
DNS              : 168.126.63.1
                   8.8.8.8
DHCP Range       : 192.168.111.150 ~ 192.168.111.180
Default Lease    : 86400초 (1일)
Maximum Lease    : 864000초 (10일)
```

### 5. 방화벽 DHCP 서비스 확인

방화벽에서 DHCP 서비스가 허용되어 있는지 확인하였다.

```bash
[root@Server-A ~]# firewall-cmd --list-service
cockpit dhcp dhcpv6-client ssh
```

`dhcp` 서비스가 방화벽에 등록되어 있는 것을 확인하였다.

직접 등록된 Port 확인

```bash
[root@Server-A ~]# firewall-cmd --list-port
```

별도의 Port 등록은 없지만 `dhcp` Service가 허용되어 있으므로 DHCP 통신이 가능하도록 구성되어 있다.

### 8. Client-L DNS 자동 할당 설정

Client-L에서 DNS 설정을 확인하였다.

```bash
[guest@Client-L ~]$ nmcli connection show ens160 | grep -E "ipv4.method|ipv4.dns|ipv4.ignore-auto-dns"
ipv4.method:                            auto
ipv4.dns:                               192.168.111.100
ipv4.ignore-auto-dns:                   예
```

기존에는 DHCP에서 전달되는 DNS를 무시하고 `192.168.111.100`을 수동 DNS로 사용하도록 설정되어 있었다.

수동 DNS 설정 제거

```bash
[guest@Client-L ~]$ sudo nmcli connection modify ens160 ipv4.dns ""
```

DHCP Server가 전달하는 DNS 정보를 사용하도록 변경

```bash
[guest@Client-L ~]$ sudo nmcli connection modify ens160 ipv4.ignore-auto-dns no
```

변경 후 확인

```bash
[guest@Client-L ~]$ nmcli connection show ens160 | grep -E "ipv4.method|ipv4.dns|ipv4.ignore-auto-dns"
ipv4.method:                            auto
ipv4.dns:                               --
ipv4.dns-search:                        --
ipv4.dns-options:                       --
ipv4.dns-priority:                      0
ipv4.ignore-auto-dns:                   아니요
```

DHCP를 통해 실제로 전달받은 DNS 확인

```bash
[guest@Client-L ~]$ nmcli device show ens160 | grep -i DNS
IP4.DNS[1]:                             168.126.63.1
IP4.DNS[2]:                             8.8.8.8
```

`/etc/resolv.conf` 확인

```bash
[guest@Client-L ~]$ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 168.126.63.1
nameserver 8.8.8.8
```

DHCP Server의 `option domain-name-servers` 설정이 Client-L에 정상적으로 적용되는 것을 확인하였다.

### 9. Client-L DHCP 로그 확인

Server-A에서 DHCP 로그를 확인하였다.

```bash
[root@Server-A ~]# journalctl -u dhcpd --no-pager | tail -n 20
```

Client-L의 DHCP 요청 확인

```text
DHCPREQUEST for 192.168.111.150 from 00:0c:29:8f:7d:df via ens160
DHCPACK on 192.168.111.150 to 00:0c:29:8f:7d:df (Client-L) via ens160
```

Client-L이 이미 기존 Lease 정보를 가지고 있었기 때문에 새로운 DORA 전체 과정 대신 기존 IP 주소에 대한 `DHCPREQUEST → DHCPACK` 과정이 확인되었다.

Lease 재사용 로그도 확인하였다.

```text
reuse_lease: lease age 641 (secs) under 25% threshold, reply with unaltered, existing lease for 192.168.111.150
DHCPREQUEST for 192.168.111.150 from 00:0c:29:8f:7d:df (Client-L) via ens160
DHCPACK on 192.168.111.150 to 00:0c:29:8f:7d:df (Client-L) via ens160
```

기존 DHCP Lease가 아직 유효하기 때문에 Client-L이 기존 `192.168.111.150` 주소를 다시 사용하는 것을 확인하였다.

### 10. Client-L DHCP Lease 확인

DHCP Server에서 Lease 파일을 확인하였다.

```bash
[root@Server-A ~]# cat /var/lib/dhcpd/dhcpd.leases
```

Client-L의 Lease 정보

```text
lease 192.168.111.150 {
  starts 2 2026/09/22 02:27:29;
  ends 3 2026/09/23 02:27:29;
  cltt 2 2026/09/22 02:27:29;
  binding state active;
  next binding state free;
  rewind binding state free;
  hardware ethernet 00:0c:29:8f:7d:df;
  uid "\001\000\014)\217}\337";
  client-hostname "Client-L";
}
```

Client-L에 `192.168.111.150` 주소가 정상적으로 임대되어 있으며 MAC 주소와 Hostname도 함께 기록되는 것을 확인하였다.

### 12. DHCP DORA 동작 과정 확인

Windows Client가 DHCP 주소를 할당받는 과정에서 Server-A의 로그를 확인하였다.

```bash
[root@Server-A ~]# journalctl -u dhcpd --no-pager | grep -E "DHCPDISCOVER|DHCPOFFER|DHCPREQUEST|DHCPACK" | tail -n 20
```

로그

```text
DHCPDISCOVER from 00:0c:29:dc:fb:d4 (DESKTOP-STH6CML) via ens160
DHCPOFFER on 192.168.111.152 to 00:0c:29:dc:fb:d4 (DESKTOP-STH6CML) via ens160
DHCPREQUEST for 192.168.111.152 (192.168.111.100) from 00:0c:29:dc:fb:d4 (DESKTOP-STH6CML) via ens160
DHCPACK on 192.168.111.152 to 00:0c:29:dc:fb:d4 (DESKTOP-STH6CML) via ens160
```

DHCP의 기본 동작 과정인 DORA를 확인하였다.

```text
DHCPDISCOVER
Client가 DHCP Server를 찾기 위해 Broadcast 전송

        ↓

DHCPOFFER
DHCP Server가 사용할 IP 주소를 제안

        ↓

DHCPREQUEST
Client가 제안받은 IP 주소의 사용을 요청

        ↓

DHCPACK
DHCP Server가 IP 주소 사용을 최종 승인
```

### 15. 최종 DHCP 할당 상태 확인

최종적으로 Server-A가 Linux와 Windows Client에게 각각 IP 주소를 자동 할당하였다.

```text
                    VMnet8
             192.168.111.0/24
                     │
              ┌─────────────┐
              │  Server-A   │
              │ DHCP Server │
              │ .111.100    │
              └──────┬──────┘
                     │
          ┌──────────┴──────────┐
          │                     │
   ┌─────────────┐       ┌─────────────┐
   │  Client-L   │       │ Windows     │
   │ .111.150    │       │ .111.152    │
   └─────────────┘       └─────────────┘
```

DHCP Server가 지정한 주소 범위에서 각각 다른 IP 주소가 정상적으로 할당되는 것을 확인하였다.

## 실습 결과

* Server-A의 고정 IP `192.168.111.100/24` 및 Gateway 확인
* `/etc/dhcp/dhcpd.conf`에 DHCP Network 및 IP 할당 범위 설정
* firewalld에서 `dhcp` 서비스 허용 상태 확인
* Client-L에 `192.168.111.150/24` DHCP 주소 할당
* Client-L의 수동 DNS 설정을 제거하고 DHCP DNS 자동 할당 구성
* Client-L에서 Gateway 및 DNS 정보 자동 할당 확인
* Windows Client에 `192.168.111.152/24` 주소 자동 할당
* DHCP의 `Discover → Offer → Request → ACK` 전체 DORA 과정 확인
* `/var/lib/dhcpd/dhcpd.leases`에서 Linux 및 Windows Client의 Lease 정보 확인
* Linux와 Windows Client가 동일한 DHCP Server로부터 서로 다른 IP 주소를 정상적으로 할당받는 것을 확인
